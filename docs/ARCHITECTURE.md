# 工程架构

## 目标
把原先单文件 HTML 原型升级为可长期维护的正式游戏工程。

## 分层
- `src/core`: 生命周期、事件总线、依赖编排。
- `src/game/state`: 纯游戏状态与类型。
- `src/game/map`: 六角坐标、地图生成。
- `src/game/systems`: 回合、城市、英雄、神器、精灵等规则系统。
- `src/render`: Three.js 世界渲染，不直接拥有规则。
- `src/ui`: DOM/UI 层，只读取状态并发出玩家意图。
- `src/data`: 运行时配置。
- `data`: 设计侧源配置，后续可由工具校验并复制到运行时。
- `public/assets`: 美术资源输出目录。
- `tools`: 后续地图编辑器、资源检查、配置校验器。
- `legacy`: 旧单 HTML 原型留档。

## 核心原则
1. 游戏规则与渲染分离。
2. 英雄、神器、精灵、国家、领袖尽量数据驱动。
3. 国家固定绑定领袖；英雄为可选招募池。
4. 精灵属于地图生态层，可刷新、捕获、作为英雄伙伴。
5. 美术资源通过稳定命名规则接入，不把生图结果写死到逻辑代码。
